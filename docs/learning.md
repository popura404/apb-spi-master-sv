# 学习与修改路线

先运行整个回归，保存一次 PASS 日志，再修改代码。每次只改一个行为，并明确
预期波形或检查条件。测试失败时先查看第一个 FAIL，不要先删除断言。

## 先认识 SystemVerilog 写法

RTL 与测试平台均使用 `.sv` 文件。阅读 RTL 时先区分三个常用写法：

- `logic` 是可表达 0、1、X、Z 的四态数据类型；它本身不决定硬件是寄存器还是
  组合逻辑，实际电路取决于驱动方式。每个信号应有明确且唯一的驱动来源。
- `always_ff` 表达时序逻辑。本项目在其中使用非阻塞赋值 `<=`，由 PCLK 边沿
  更新状态；需要异步复位的过程还声明复位下降沿。
- `always_comb` 表达组合逻辑，自动确定敏感信号。本项目使用阻塞赋值 `=`，
  并在各分支赋值或先给默认值，避免遗漏赋值而推断锁存器。

连续赋值 `assign` 仍适合简单组合表达式。测试平台中的 `initial`、普通 `always`、
`task`、`function`、延时和事件等待也是合法的 SystemVerilog 写法；仿真激励不需要
改写成 RTL 的 `always_ff`。运行脚本已选择支持 SystemVerilog 的编译方式。

## 1. 读懂 FIFO

先读 `rtl/sync_fifo.sv` 和 `tb/tb_sync_fifo.sv`。

- 区分存储地址指针与元素计数器；手算深度为 2 时的满、空、回绕。
- 分析 push/pop 的四种组合，特别是满时两者同时为 1。
- 理解为什么存储阵列无需整体复位：复位后的 level=0 已让旧内容不可见。
- 运行 `python scripts/run.py sim --top tb_sync_fifo --fifo-depth 2`。

练习：把 FWFT 改为同步读接口，再分析上层调度需要增加哪些等待周期。
这会改变模块合同，应同时新增适合新接口的测试。

## 2. 读懂 SPI 边沿

读 `rtl/spi_shift.sv`，画出 Mode 0 和 Mode 3 各一个字节的 16 个边沿。

- 看清首位何时就绪、采样发生在哪个边沿、何时可以更新 MOSI。
- 分别用 0x80、0x01、0xA5 验证位序，避免只测试回文位图。
- 理解为什么最后一位采样与生成 rx_data 之间需要避免使用旧的寄存器值。
- 运行 `python scripts/run.py sim --top tb_spi_shift`。

练习：添加可配置字长；先定义 4/8/16 位的传输和寄存器行为，再写测试。

## 3. 读懂 APB

读 `rtl/apb_spi_master.sv` 的地址译码和 `write_ok/read_ok`。

- 找出 SETUP 阶段为什么不会误写 TX FIFO。
- 在波形中观察 PSEL 持续有效的背靠背读写。
- 理解 PSLVERR 的有效阶段，以及为什么错误访问不应改变配置寄存器。
- 读取 [寄存器表](specification.md)，手写一次两字节传输的访问顺序。

练习：加入只读版本号寄存器，先给它确定地址和复位值，再扩展测试。

## 4. 理解系统调度

关注 `remaining`、`byte_active`、`engine_start` 和 `engine_done`。

- 解释为何 RX 满时要在下一字节开始前停住。
- 解释 LENGTH 大于 FIFO 深度时，为什么等 DONE 再读取会停滞。
- 解释 ABORT 为什么要同时处理移位器、片选和两侧 FIFO。
- 用 `python scripts/run.py sim --waves`，观察真实外部 MISO 与内部回环的区别。

练习：为等待状态添加可配置超时。先决定超时是否清 FIFO、产生何种中断，
并增加临界周期的测试。不要仅增加一个计数器而留下模糊的软件行为。

## 5. 理解验证

系统测试通过外部 APB 和 SPI 引脚观察设计。SPI 从机模型在非采样边沿驱动
MISO，在采样边沿比对 MOSI，并检查边沿间距和片选；因此不依赖读 DUT 内部
寄存器来证明正确。回环另外测试，不能替代独立从机模型。

检查内容包括正常场景、边界、错误操作、复位和多参数配置。通过一次随机种子
不等于证明全部输入正确；增加随机种子前，先确认关键边界有定向测试。
当前没有提供功能覆盖率百分比或形式验证证明，不应自行填写这类指标。

## 6. 读时序与资源报告

运行 `python scripts/run.py synth --implement`，打开 `build/synth/` 的报告。

- 区分综合后的估计时序与布局布线后的时序。
- 查找 WNS、WHS、LUT、FF、存储资源，找到最差路径两端寄存器。
- 对比不同 FIFO 深度时的资源变化，保持器件、时钟和实现选项一致。
- 不要直接把 `1 / (周期-WNS)` 作为已验证的最高工作频率。

适合做自己的改进：减少字节间空隙、增加 RX 水位中断，或比较 FIFO 的不同
存储实现。完成后保留修改前后的测试和报告，写清楚性能收益与资源代价。
